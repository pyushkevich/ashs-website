# Notes for working on the ASHS website

Documentation site for HyperASHS and ASHS Classic, built with Zensical and served at https://ashs.itksnap.org. See README.md for the editing workflow; this file collects what is easy to get wrong.

## Build, check, publish

- `python -m venv .venv && .venv/bin/pip install -r requirements.txt` (Zensical is pinned; it is pre-1.0 and its template API changes between versions).
- Preview: `.venv/bin/zensical serve -a localhost:8765`. Build: `.venv/bin/zensical build`.
- Do not run `zensical build --clean` while `serve` is running: it panics on the shared cache directory. The serve process also rewrites `site/` in the background, so if a link check suddenly reports every CSS/icon file missing, wait a moment and rerun.
- After every change: build, then `python3 scripts/check_links.py` (checks internal links, images and `#anchors`; should report 0).
- Pushing to `main` deploys via `.github/workflows/docs.yml` (GitHub Actions → Pages), live within a couple of minutes. The custom domain is set in the repo's Pages settings plus a CNAME record at Register.com (`ashs` → `pyushkevich.github.io`); there is no CNAME file in the repo.
- Commit messages end with the `Co-Authored-By` line; the user has been happy for finished changes to be committed and pushed to `main` directly.

## Structure

- `zensical.toml` holds the nav. Top-level sections are Home, HyperASHS, ASHS Classic and Resources. Every new page needs a nav entry and, under Resources, a line in `docs/resources/index.md`.
- HyperASHS and ASHS Classic pages have **parallel layouts** (Quick Start, MRI Data, Cloud, Local, ...). `[project.extra.counterparts]` maps each page to its equivalent in the other version, in both directions; the header toggle and the "equivalent page" link use it. When adding a page to one section, add or update its counterpart mapping.
- HyperASHS has priority: it is the default section, and ASHS Classic pages carry a banner pointing to it.
- Menu labels are short ("Cloud", "Local") because the version toggle already says which version you are in; full names belong in page titles.

## Templates and styling (`overrides/`, `docs/assets/css/extra.css`)

- The look imitates the old Google Site (https://sites.google.com/view/ashs-dox/): dark full-width header with a horizontal dropdown menu, gradient title banner, blue headings.
- `partials/topnav.html` builds the menu from `nav.items` (iterating `nav` directly yields empty items). It shows Home, the children of the active version section, then Resources.
- The horizontal menu appears at ≥80em (1280px); below that the sidebar/drawer takes over. If you add top-level menu items, re-check the header at 1280px (headless Chrome screenshot) and adjust the breakpoint in `extra.css` and README.md.
- The page title is rendered in the banner by `main.html`; `partials/content.html` suppresses the duplicate h1 when a page sets `banner:` in its front matter.
- Colors are tokens with light and dark variants; check both palettes after styling changes.

## Content and facts

- Verify claims about `hrashs` options and behavior against the HyperResASHS source (`../HyperResASHS/hyperresashs/ashs_cli.py`) rather than the README, which has lagged behind. Model IDs, Hugging Face repos and outputs are listed on `resources/models-and-atlases.md`.
- Key facts that have been checked: HyperASHS needs ITK-SNAP 4.6+ (its segmentations are in a different voxel space from the main image); `-k` disables SSL verification for Hugging Face downloads; users never need to download HyperASHS models by hand; ASHS Classic atlases are on Hugging Face (`upennpatchlab/ashs_atlases`) and NITRC.
- The HSG harmonized protocol site is **hippocampalsubfields.com** (the .org domain does not exist). Mentions of HSG should link to it.
- The HyperASHS paper is Li et al., NeuroImage 342:122294 (2026), doi:10.1016/j.neuroimage.2026.122294. The PDF in `paper/` is Elsevier-copyrighted and gitignored: never commit it or copy its figures.
- Don't invent roles, affiliations or descriptions of people or atlases (e.g. on Contributors or Models and Atlases). Use neutral wording and ask the user.
- The old Google Site has a banner pointing here. A few old pages referenced from `ashs/local/atlas-t2.md` (config example, heuristic rule syntax) only survive in the Wayback Machine.

## Figures

- HyperASHS figures in `docs/assets/images/hyperashs/` are generated by scripted ITK-SNAP sessions in `figures/` (see `figures/README.md`): `make_data.sh` once, then `make_figures.sh [name ...]`, which writes straight into the docs. Don't hand-edit those PNGs; change the script and regenerate, so they stay reproducible. `figures/work/` (~70 MB) is not committed.
- T2 display images are clipped just above the 99.9th percentile inside the segmentation; without it ITK-SNAP's default window leaves the MTL nearly black. Don't apply the same clipping to T1 (it washes out gray/white contrast).
- 3D renderings use a black background, as on the old ASHS site. Terminal output belongs in code blocks, not screenshots.
- ASHS Classic images in `docs/assets/images/ashs/` were migrated from the Google Site.
- The favicon set (`docs/favicon.ico`, `docs/assets/images/favicon-*.png`, `apple-touch-icon.png`) was made from `home_3d_pmc_t1.png` (one hemisphere, black made transparent, rotated 40°).
